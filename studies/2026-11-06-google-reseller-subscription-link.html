1 What the link actually is

The link is not built by Jio’s screen or app. It is a Google URL whose last segment is a signed, short-lived, single-use token minted by Google’s Payments Reseller Subscription API. Jio is a Google reseller/billing partner; its backend asks Google for a token, and Google glues it onto the activation path.

EndpointPathUse
Create intenthttps://serviceactivation.google.com/subscription/new/<token>End user creates + activates a brand-new subscription
Entitle intenthttps://serviceactivation.google.com/subscription/entitle/<token>End user links an already-provisioned subscription to their Google account
Sandboxhttps://serviceactivation.sandbox.google.com/subscription/new/<token>Same, but pre-production

Anatomy of a real Jio token (verified 2026-09)

A live token shared for the Jio offer was inspected byte-for-byte:

https://serviceactivation.google.com/subscription/new/AQCpiIFGJKlYJG59Qeh‑R_zayuBXvyh…2HQ==
📦

205 bytes

base64url‑encoded, opaque. Decodes to binary starting 01 00 (a protobuf envelope), not a JSON you can read.

🕐

~1 hour TTL

Short‑lived by default. Google returns an expireTime in the same call that mints it.

🔒

Single‑use + signed

Bound to the intent payload server‑side. The end user can’t forge, share, or replay it.

Proof it’s real: opening the Jio token (with a browser User‑Agent) returned HTTP 200 → 2 redirects → accounts.google.com/v3/signin. That is Google’s own “Google Managed Signup” activation UI. The token is just a key that unlocks that UI for one person, one offer, for one hour.

2 The reseller / billing‑partner model

Google’s Reseller Subscription API lets a partner (Jio, G2A, an operator, a telco) resell a Google product (Google One, Google AI Pro, YouTube, Play Pass) to end users, while Google handles identity, billing and entitlement. The partner never sees the user’s Google password.

Partner (Jio)
Knows the customer
Owns the user (Jio number, age, plan tier). Runs eligibility + billing rules.
→
Google
Reseller Subscription API
Holds products & promotions, mints tokens, creates the subscription, charges/renews.
→
End user
Signs in + activates
Opens the link, logs in with a Google Account, taps “Activate now”.

Two signup styles

Google Managed Signup (used here): the partner mints a userSession token and redirects the user to Google’s own activation page. No OAuth consent screen for the partner. Partner Managed Signup (OAuth): the partner runs its own OAuth flow and calls subscriptions.create directly.

Two ways to make a sub

Create intent → brand‑new subscription (this offer). Entitle intent → link a pre‑provisioned sub to the user (subscriptions.provision first, then :entitle).

Who is the “partner” here? Jio (Reliance). Google’s own announcement confirms it: “Through a new strategic partnership with Reliance… giving millions of their users access to the Google AI Pro plan at no extra cost for 18 months.” That partnership is what lets Jio’s backend call userSessions:generate at all.

3 How the token is created (step by step)

The whole minting is server‑to‑server. The end user only ever sees step 6.

1

Eligibility check Jio

User taps “Claim” in MyJio. Jio verifies the offer rules — here: age 18–25, an active Jio plan of ₹349 or above, one claim per Jio number.

2

Sign an RS256 service‑account JWT Jio backend

Jio’s backend (a Google service account) builds a JSON Web Token signed with the SA private key, requesting scope …/auth/payments.reseller.subscription. This proves “this is really our partner” — see §4.

3

Swap the JWT for an OAuth access token Google

POST https://oauth2.googleapis.com/token with grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer and the signed assertion. Google returns a short‑lived access_token for the service account.

4

Call userSessions:generate with an intent Google

POST …/v1/partners/{partner}/userSessions:generate with a createIntent describing exactly what to give: the product (Google AI Pro), the promotion (free 18 months), the partner’s own id for this user, and the region. See §5.

5

Google mints the token Google

Google encrypts the intent + request into the signed blob and returns {"token":"…","expireTime":"…"}. Token size scales with the intent payload.

6

Build the link & send it to the user Jio

Jio returns https://serviceactivation.google.com/subscription/new/ + token. That is the exact link. It’s delivered via the app redirect / a page / SMS — then the user opens it, signs in, and activates.

You cannot self‑generate one. The token only exists after the partner’s backend passes its own eligibility check and asks Google to mint it. Anyone selling “Gemini Pro keys” (G2A, Telegram channels, etc.) is a separate reseller account running this same API and handing you the token they minted — you just activate it with your own account.

4 The RS256 service‑account JWT

This is the credential that proves the request comes from a legitimate partner. It’s a standard Google service‑account assertion (the same mechanism Cloud IAM uses), just with a reseller scope. The msasoup bot implements it with no extra dependency — only the cryptography package that’s already in requirements.txt.

Claims

FieldValueNotes
iss<service.account.email>.iam.gserviceaccount.comThe partner’s service account
scopehttps://www.googleapis.com/auth/payments.reseller.subscriptionReseller API access
audhttps://oauth2.googleapis.com/tokenGoogle token endpoint
iatnowIssued‑at (epoch)
expnow + 3600Expiry — 1 hour

The full flow (runnable, no google‑auth/PyJWT)

# 1) build + sign the RS256 JWT (cryptography only)
header  = {"alg": "RS256", "typ": "JWT"}
claims  = {"iss": sa["client_email"],
           "scope": "…/payments.reseller.subscription",
           "aud": "https://oauth2.googleapis.com/token",
           "iat": now, "exp": now + 3600}
sig     = rsa_key.sign(b64(header) + b"." + b64(claims),
                       padding.PKCS1v15(), hashes.SHA256())
jwt     = b64(header) + b"." + b64(claims) + b"." + b64(sig)

# 2) swap for an OAuth access token
POST https://oauth2.googleapis.com/token
     grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer & assertion=<jwt>
# → {"access_token":"…","expires_in":3600}

# 3) mint the user session (see §5)
POST …/v1/partners/<partner>/userSessions:generate
     Authorization: Bearer <access_token>
Verified in the msasoup tooling: the JWT is generated from a real RSA key, the signature is checked with the public key (PKCS1v15 / SHA‑256), claims round‑trip correctly, and changing any input changes the token — all covered by unit tests.

5 userSessions:generate — the actual call

One call turns “give this user Google AI Pro free for 18 months” into a token. The body is a createIntent whose subscription is identical to what partners.subscriptions.create would take.

POST https://paymentsresellersubscription.googleapis.com/v1/partners/jiopartner/userSessions:generate
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "intentPayload": {
    "createIntent": {
      "parent": "partners/jiopartner",
      "subscriptionId": "<partner-chosen unique id>",
      "subscription": {
        "partnerUserToken": "<jio user id, ≤63 ASCII chars>",
        "serviceLocation": { "regionCode": "IN" },
        "lineItems": [
          {
            "product": "partners/jiopartner/products/GOOGLE_AI_PRO",
            "lineItemPromotionSpecs": [
              { "promotion": "partners/jiopartner/promotions/FREE_18MO" }
            ]
          }
        ]
      },
      "cycleOptions": { /* optional */ }
    }
  }
}

// → 200 OK
{
  "userSession": {
    "token": "AQCpiIFGJKlY…(205 bytes)…",
    "expireTime": "2026‑11‑06T13:00:00Z"
  }
}
// link = "https://serviceactivation.google.com/subscription/new/" + token

partnerUserToken

The partner’s own id for the end user (e.g. a Jio customer id). ≤63 ASCII chars. It’s what lets the partner map the Google subscription back to its customer.

subscriptionId

Chosen by the partner, unique per sub. It’s the idempotency key: re‑minting tokens for the same id never double‑fulfills, so tokens can be freely regenerated.

product + promotion

Names Google registered for the partner. The promotion is the free‑18‑months deal; enableOfferOverride can let Google swap in a different eligible offer.

serviceLocation

Where the service is provided (ISO region, e.g. IN). Drives regional pricing/eligibility.

Token hygiene: Google’s docs are explicit — generate the token dynamically, for an authenticated user, and don’t paste it into an unauthenticated channel (SMS/email) where it could be grabbed by someone else. It’s a bearer for that one activation.

6 Activation & the Pub/Sub round‑trip

The link is only half the story. Once the user activates, Google tells the partner what happened over Cloud Pub/Sub — this is the source of truth the partner must listen to.

User
Opens link → Google sign‑in → “Activate now”
Google creates the sub and links the user’s Google Account.
→
Google
Publishes a Pub/Sub message
The subscription resource as JSON (base64) + attributes, to the partner’s topic.
→
Partner (Jio)
Receives endUserEntitled=true
Knows the specific user succeeded — keeps it alive while their plan is active.

What the notification carries

FieldMeaning
dataBase64 JSON of the full Subscription resource (state, products, partnerUserToken, endUserEntitled, times…)
attributes.statee.g. STATE_ACTIVE, STATE_CANCELLED
attributes.endUserEntitledtrue once the user linked their Google account
attributes.sequenceNumberPer‑sub counter — use it for idempotency / out‑of‑order handling
attributes.cancellationReasone.g. CANCELLATION_REASON_ACCOUNT_CLOSED
Why the sub can quietly die: for this offer the 18‑month access stays only as long as an eligible recharge remains active. Google’s lifecycle events (STATE_CANCELLED, …/past_due, …/account_closed) are how Jio — and any partner — finds out. That’s why the T&Cs hinge on keeping a ₹349+ plan active.

7 Build your own partner integration

Everything below is what you stand up before you can mint a single token. The Google Integration Team hands you the pieces you can’t self‑serve (partner id, product/promotion ids, Pub/Sub topics).

Setup checklist

  • ✓Two GCP projects — one for staging, one for production. Tell Google your project name, id and number so they can configure your client.
  • ✓Enable the API — in the Cloud Console: APIs & Services → Library → search “Payments Reseller Subscription API” → Enable. Unlocks paymentsresellersubscription.googleapis.com (prod) and preprod‑… (sandbox).
  • ✓Create a service account (per environment) — for server‑to‑server calls like provision and userSessions:generate.
  • ✓Grant the IAM role — Payments Reseller Admin (Beta) on that service account (full access to subscriptions, products, promotions). If you run on Compute/App Engine the default SA may already have it.
  • ✓Create an SA key (JSON) — this is the sa that signs the RS256 JWT in §4.
  • ✓Get your partner/product/promotion ids from the Google Integration Team — you can’t list‑and‑guess them into lineItems.
  • ✓Set up Pub/Sub — receive your topic ids from Google, allow‑list your subscriber SA, subscribe (filtered on attributes.state if you want), and handle sequenceNumber.
  • ✓(OAuth style only) Configure the OAuth consent screen + client id/secret with the reseller scope, and set authorized JavaScript origins / redirect URLs. Skip for Google Managed Signup.
  • ✓Pass Google’s test requirements — there’s a formal onboarding/test gate before launch.

Minimum env to go live (what the msasoup /gemini tool reads)

GEMINI_JIO_PARTNER — your partners/{partner} id
GEMINI_JIO_PRODUCT — partners/{partner}/products/{productId}
GEMINI_JIO_PARTNER_USER_TOKEN — your per‑user id
GEMINI_JIO_SA_FILE — path to the SA JSON key
GEMINI_JIO_REGION — default IN
GEMINI_JIO_PROMOTION — optional free‑trial offer
GEMINI_JIO_ENV — prod / sandbox
Fail‑open by design: the msasoup tool tries the real flow when the SA is configured, and otherwise returns a template — the exact userSessions:generate request it would send, the link shape it would produce, and the list of env vars still missing. No dead end.

8 The Jio specifics (the concrete numbers)

🎁 The offer

Google AI Pro free for 18 months (≈ ₹35,100 value): Gemini 2.5 Pro/3, Veo + Nano Banana image/video, NotebookLM, higher limits, 2 TB Google One storage (Photos/Gmail/Drive).

📞 Eligibility

Jio users age 18–25 on an active Unlimited 5G plan of ₹349+ (prepaid or postpaid). Once per Jio number. DOB comes from KYC — can’t be changed.

🧭 Claim path

MyJio app → “Google Gemini Offer” banner → register interest → Claim → sign in with your Gmail → Activate now. Fallback page: jio.com/google-gemini-offer.

⚠️ Status (Nov 2026)

Jio decommissioned its redemption gateway (tiny.jio.com/loginrecharge + selfcare campaign URL now return 403). Subscriptions already linked before the patch stay active to 01 May 2028, provided the ₹349+ plan stays continuously active.

What this proves: even with the user‑facing link 403’d, the underlying mechanism is still the Google Reseller Subscription API. The 403 is on Jio’s gateway (which mints the token), not on Google’s activation endpoint. A token that was already issued still works until it expires — which is exactly why third parties resell “fresh keys.”
