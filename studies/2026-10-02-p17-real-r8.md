# P17 real-R8 verification — the @Metadata name-recovery ceiling (v0.22, PR #6)

Date: 2026-10-02 · Branch: feat/native-r2-verified (folded) · Author: Aliph (Anam-directed "contineu pending")

## Gap this closes

P17's disclosed limit: **single-fixture coverage** — one kotlinc/d8 shape,
never a real R8-obfuscated DEX (which is P17's *flagship* use case: "R8
renames every DEX name, but @kotlin.Metadata carries the originals"). Its
docstring claimed full recovery of "ORIGINAL (pre-R8) names". This round
built REAL R8 outputs of the same sample and ran the real decoder on them.

## What was built (real toolchain, user-space)

- `r8-9.4.28.jar` from Google Maven (20 MB, `com.android.tools.r8.R8`)
- Re-compiled `tests/fixtures/ktmeta/sample.kt` (the 6-class ground truth)
  with kotlinc 2.0.21 → `appclasses.jar` (6/6 `.class` carry @Metadata)
- R8 run A (default config + `allowobfuscation`): obfuscates to a–f
- R8 run B (default + `-keepattributes *Annotation*`): obfuscates to a–f
  AND keeps @Metadata
- d8 → committed fixtures:
  - `tests/fixtures/ktmeta_r8/classes-kept.dex` (5,576 B)
  - `tests/fixtures/ktmeta_r8/classes-stripped.dex` (3,556 B)
- Recipe (scratch): `/opt/data/cache/scratch/r8work/` (pg.txt, pg-strip.txt)

R8 gotchas (real, not guessed): `-include-runtime` fat-jars poison R8
(treats stdlib as program code — 800-class garbage output); R8 wants
`--pg-conf` (not positional) for the config; config extension must be `.txt`;
`-dontmerge` does NOT exist in R8; and **R8 strips @Metadata by default —
`-keepattributes *Annotation*` is what keeps it** (why real apps carry that
rule).

## What the real R8 DEX proved (the finding)

The decoder was run on REAL R8 output and behaved correctly; the *claim*
needed correction. Three observed regimes:

1. **Plain (un-R8'd) DEX** (`ktmeta/classes.dex`): d2 carries the ORIGINAL
   names → full recovery (`CheckoutService`, `charge`, `gateway`, …).
2. **R8'd, @Metadata kept**: 6 @Metadata records survive, class names
   obfuscated (a–f), but **d2 is POST-R8** — the `fq_name`/function names
   decode to the obfuscated names (`b`, `a`), while **property names
   survive** (gateway, totalCents, amountCents, sku, orderId, reason,
   MAX_CENTS). Recovery is PARTIAL.
3. **R8'd, default config**: R8 strips @Metadata entirely → 0 records;
   `recover_names` reports "no @kotlin.Metadata" (honest, not a failure).

So "original (pre-R8) names" is guaranteed only for regime 1. For a real
R8'd DEX the ceiling is whatever d2 still contains — and whether @Metadata
survives at all is a *build-config* property (`keepattributes`), not a
decoder property.

## Honest limits

- One R8 version (9.4.28) and one sample app; the regime-2 "property names
  usually survive" is observed, not guaranteed across all R8 versions/configs
  (data classes survive because their fields are retained; a fully
  obfuscated app with `-keepallowobfuscation` on members could rename more).
- This verifies the STATIC ceiling (what the DEX contains). A real app where
  `keepattributes` is set and property names survive still yields useful
  partial recovery — that is the honest value, now stated, not oversold.
- The R8 DEX fixtures are synthetic-but-real (genuine kotlinc + R8 9.4.28 +
  d8 output of the committed sample).
