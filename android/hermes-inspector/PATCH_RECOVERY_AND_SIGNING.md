# Vibe APK Patch Studio v0.8 — owner-controlled editing and signing

## Safe mobile workflow

Import a **legitimately owned or authorized** APK through Android's document picker, inspect DEX and compiled Android resources, select a non-executable plain-text asset under assets/ or res/raw/, edit a temporary copy and stage it. Search-and-replace is exact and limited to approved plain-text assets; no runtime bytecode, signing data, purchase logic, identity controls or native code is changed.

The app records the SHA-256 of the original APK and before/after hashes for each staged asset. Up to 12 assets can be staged with 8 previous states available for undo. The patch queue is stored in app-private atomic checkpoints keyed by the exact original APK hash, so reimporting the *same* APK can restore the queue after a process restart. A modified or unrelated APK is rejected rather than applying stale edits. Use the reset control to delete the saved queue.

The app performs read-only **Preflight** checks of the staged hashes and ZIP entries before export. It writes the repack to a temporary internal file, verifies every changed entry, verifies the input APK is unchanged, then moves to a **new non-overwriting unsigned file** and exports it through the Android document provider. When the provider supports reopening the file, exported bytes are SHA-256 checked; otherwise verification is clearly marked unavailable. Output is not signed, aligned, or installable directly. ZIP entries may be recompressed, and original signature metadata is removed deliberately.

## Actual APK signing, if you own a legitimate signing key

On an authorized build environment with Android SDK build-tools installed:

1. Keep the release keystore outside source control and never expose its passwords.
2. Recheck the repacked APK contents and any manifest/resource changes.
3. Run `zipalign -p -f 4 input-unsigned.apk output-aligned.apk`.
4. Sign `output-aligned.apk` with `apksigner sign --ks <private-keystore> --ks-key-alias <alias> ...`; enter secrets through a secure prompt, not logs.
5. Verify `apksigner verify --verbose --print-certs output-aligned.apk`.
6. Verify installation only on devices/accounts where the signing certificate is authorized. Existing Android installations cannot be upgraded using another developer's certificate.

The Vibe Inspector debug APK itself is generated by CI with a per-run debug certificate. A persistent private release key is **not configured** and was not created or uploaded in this project. Debug updates may require uninstalling the previous Inspector build after exporting needed reports.

## Explicit limits

The application cannot reconstruct exact original Java/Kotlin/Dart source or build arbitrary new runtime code from DEX/Flutter/native machine code. It does not alter premium entitlements or disable payments. Android compiled XML and resources.arsc have bounded inspection, not arbitrary binary rewriting. A source project is strongly preferred for SDK changes such as legitimately removing an advertising integration: remove SDK dependencies, identifiers and initialization from **your own project**, verify resulting features, then rebuild and sign normally.

Real Android 16 installation, landscape accessibility, low-memory performance and interrupted external document-provider behavior are not fully reproduced by JVM CI. Keep Draft PR #34 unmerged until those device tests and stable release signing pass.

## v0.8.1 behavior and limitations

- Sequential exact replacements now use the current staged text of each eligible file. A second replacement can build on the first without silently reverting its edits.
- Patch JSON checkpoints are rejected before parsing if nesting exceeds 20 levels, braces are mismatched, or quotes are unterminated.
- The on-device **Preflight staged patches** control checks each changed source entry against its SHA-256 and rejects unsafe ZIP names, duplicates, unexpected sizes, and excessive compression. No bytecode is executed.
- Output publication uses a non-replacing move. The move is not promised crash-atomic on every Android filesystem; a failed Android document-provider write may leave partial external output. Verify the final reported SHA-256.
- Physical Android 16, TalkBack, landscape and memory-pressure acceptance still require a real device and the user's authorized test APK.
